Docker Desktopのインストールが完了しました。保留していた「マイグレーション履歴の再構築」のステップ4（新規プロジェクトでの検証）を、ローカルのSupabase CLIスタックで進めてください。

## やってほしいこと

1. Docker Desktopが起動していることを確認する（`docker ps` 等でDockerデーモンに接続できるか確認）
2. リポジトリルートで `supabase start` を実行し、ローカルのSupabaseスタック（PostgreSQL含む）を立ち上げる
3. `supabase db reset` を実行し、再構築したマイグレーション履歴（`CREATE TABLE`から始まるベースラインを含む）を最初から全て適用する
4. 適用後、以下が期待通りになっているか確認する
   - `clients` / `departments` / `qq_conditions` / `survey_responses` の4テーブルが作成されていること
   - `departments` / `qq_conditions` が `(name, client_code)` / `(id, client_code)` の複合主キーになっていること
   - 各テーブルのRLSポリシーが本番・テスト環境と同じ内容で作成されていること
   - 確認方法はローカルのSupabase Studio（`supabase start` 実行後にURLが表示されます）、または `psql`（Docker経由で `supabase db psql` のようなコマンドがあれば利用）のどちらでも構いません
5. 確認が取れたら `supabase stop` でローカルスタックを停止する
6. 検証結果をGitHub Issueの「新規プロジェクトでの検証」のチェックボックスに反映し、`docs/01_現行モック整理.md` の「4.3 マイグレーション履歴」の記述も、実行検証まで完了した旨に更新する

## 注意
- 本番・テスト（クラウド上の`survey-app` / `survey-app-dev`）には一切接続・変更しないでください。ローカルスタックのみで検証します。
- ローカルスタックのデータはテスト用の一時データなので、`supabase stop` 後に破棄されても問題ありません。
- 検証中に何らかの不整合（型のズレ、RLSポリシーの記述ミスなど）が見つかった場合は、その内容と対応方針を報告してください。まだ本番・テストに影響していないので、落ち着いて修正できます。
