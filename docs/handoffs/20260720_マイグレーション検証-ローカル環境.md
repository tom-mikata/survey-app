Issue「選択肢C: DBスキーマ・コード構造の土台整備」の1番目の項目のうち、保留になっている「新規プロジェクトでの検証（ステップ4）」を進めてください。

## 背景
無料プランのSupabaseプロジェクト数上限（2つ）に達しているため、検証用の3つ目のクラウドプロジェクトを作成できませんでした。そのため、クラウド上に新規プロジェクトを作らず、Supabase CLIのローカル開発スタックで同等の検証を行います。

## やってほしいこと

1. Docker Desktopが起動していることを確認する（未起動なら起動する）
2. リポジトリルートで `supabase start` を実行し、ローカルのSupabaseスタック（PostgreSQL含む）を立ち上げる
3. `supabase db reset` を実行し、再構築したマイグレーション履歴（`CREATE TABLE`から始まるベースラインを含む）を最初から全て適用する
4. 適用後、以下が期待通りになっているか確認する
   - `clients` / `departments` / `qq_conditions` / `survey_responses` の4テーブルが作成されていること
   - `departments` / `qq_conditions` が `(name, client_code)` / `(id, client_code)` の複合主キーになっていること
   - 各テーブルのRLSポリシーが本番・テスト環境と同じ内容で作成されていること
   - （確認方法はローカルのSupabase Studio、または `psql` での直接確認のどちらでも構いません）
5. 確認が取れたら `supabase stop` でローカルスタックを停止する
6. 検証結果をGitHub Issueの「新規プロジェクトでの検証」のチェックボックスに反映し、`docs/01_現行モック整理.md` の「4.3 マイグレーション履歴」の記述も、マイグレーション履歴の欠落が解消された旨に更新する

## 注意
- 本番・テスト（クラウド上の`survey-app` / `survey-app-dev`）には一切接続・変更しないでください。今回はローカルスタックのみで検証します。
- ローカルスタックのデータはテスト用の一時データなので、`supabase stop` 後に破棄されても問題ありません。
