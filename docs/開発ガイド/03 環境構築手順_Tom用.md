# 環境構築手順（Tomさん用）

作成日: 2026年8月2日
対象: プロジェクトリーダー（藤田/Tom）
関連: `docs/03_チーム開発プロセス提案.md`、`SETUP.md`、`docs/06_環境構築手順_新規メンバー用.md`

新しいメンバー（シニアエンジニア・学生エンジニア）が参加する前に、Tomさんが事前に準備しておくべきことをまとめます。メンバーごとに1回ずつ、以下の招待作業を行ってください。

## 1. アカウント種別ごとの権限方針（先に決めておくこと）

全員に同じ権限を渡す必要はありません。以下を基本方針として提案します。

| サービス | シニアエンジニア（中間さん） | 学生エンジニア |
|---|---|---|
| GitHub リポジトリ | Write権限 | Write権限 |
| Supabase テスト用（`survey-app-dev`） | メンバー招待（Developer以上） | メンバー招待（Developer以上） |
| Supabase 本番用（`survey-app`） | メンバー招待（閲覧〜Developer） | **招待しない**（Tomさん・シニアエンジニアのみ） |
| Vercel プロジェクト | メンバー招待 | メンバー招待（任意。デプロイログ確認用） |

本番のSupabaseには実際のクライアントデータが入っているため、学生エンジニアには渡さず、テスト環境だけで開発・検証してもらう運用を推奨します。この方針で問題なければ、以下の招待作業を進めてください。

## 2. GitHubの準備

1. 各メンバーからGitHubのユーザー名（またはメールアドレス）を聞く（未登録なら [github.com](https://github.com) でアカウント作成を依頼）
2. `https://github.com/tom-mikata/survey-app` → Settings → Collaborators and teams → Add people
3. 上記のユーザー名を入力し、Write権限で招待する
4. 招待メールが届くので、相手に承認してもらう

## 3. Supabaseの準備

Supabaseダッシュボード（[supabase.com](https://supabase.com/dashboard)）で、それぞれのプロジェクトを開いて行います。

1. `survey-app-dev`（テスト用）プロジェクトを開く → Project Settings → Team → Invite a member
2. メンバーのメールアドレスを入力し、招待する（全員）
3. `survey-app`（本番用）は、シニアエンジニアのみ同様に招待する（学生エンジニアは招待しない）

招待を受けたメンバーは、`survey-app-dev`のProject Settings → API から、`Project URL`と`anon key`を控えて`.env.local`に設定します（手順は`docs/06`参照）。この値をTomさんから直接渡す必要はなく、各自がSupabaseにログインして自分で確認できます。

## 4. Vercelの準備

1. Vercelダッシュボード → プロジェクト（`survey-app`）→ Settings → Members → Invite Member
2. メンバーのメールアドレスを入力して招待する
3. すでに設定済みの環境変数（`NEXT_PUBLIC_SUPABASE_URL`等）は、Preview環境全体に対して設定済みなので、新しいメンバーがブランチを作ってもそのまま動作確認できるはずです

## 5. Claude Codeについて

Claude Codeは各自が自分のClaudeアカウントでログインして使うツールなので、Tomさん側で招待するようなアカウント作業は基本的に不要です。各メンバーに、以下を伝えてください。

- Claude Codeを使うには、Claude（Anthropic）のアカウントと、Pro以上のプランまたはAPI利用契約が必要
- 個人でアカウントを持っていない場合は、各自で [claude.com](https://claude.com) から作成してもらう
- チーム全体でまとめて契約・管理したい場合は、Anthropicの Team/Enterprise プランを検討する（人数や予算次第。今は各自の個人プランで開始して問題ない）

## 6. シークレット（APIキー等）の共有について

現状、一部の秘密情報（Resend APIキー等）はEvernoteで管理されています。学生エンジニアの入れ替わりが想定されるため、新しいメンバー全員にEvernoteへのアクセス権を渡すのではなく、以下を推奨します。

- Supabase・Vercelの認証情報は、各自が2〜3節の招待を通じて自分のアカウントで直接取得する（Tomさんが値をコピーして渡す必要がない）
- どうしても個別に共有が必要な値（Resend APIキー等）が出た場合は、チャットやメールへの直接貼り付けは避け、1Password等の共有ツールの導入を検討する（`docs/03` 7章参照、未着手）
