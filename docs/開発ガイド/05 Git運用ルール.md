# Git運用ルール

## ブランチ構成

| ブランチ | 役割 | 直接pushして良いか |
|---|---|---|
| `main` | 本番相当。マージすると自動的にVercel本番環境へデプロイされ、**本番Supabase**に接続する | ❌ 禁止。必ずPR経由 |
| `feature/xxx` | 機能追加・修正用の作業ブランチ | ✅（自分のブランチのみ） |

ブランチ名の例：
- `feature/add-department-filter`
- `fix/graph-label-overlap`

日本語での命名でも構いませんが、英語の方が後で検索・grepしやすいので推奨します。

## 基本的な作業の流れ

1. `main` から最新を取得してブランチを作成
   ```
   git checkout main
   git pull
   git checkout -b feature/xxx
   ```
2. 実装・コミット（こまめにコミットしてOK）
3. GitHubにpushしてPull Requestを作成
4. PRを作成すると**Vercel Preview URL**が自動発行される → 自分でそのURLを開いて動作確認
5. 熊澤さんにレビュー依頼
6. 指摘があれば同じブランチに追加コミット
7. 承認後、`main`にマージ

## 特に気をつけること

- **`main`へのマージ = 本番デプロイ = 本番Supabase（実データ）への接続** です。マージ前は必ずPreview URLでの動作確認とレビュー承認を経てください。
- 迷った時や大きめの変更をする時は、実装前に藤田さんか熊澤さんに一声かけてください。
- コンフリクトが発生したら、自己判断で強制的に解決せず、まず相談してください。

## PRの書き方（最低限）

- タイトル：何をしたか一行で（例：「部署フィルターの追加」）
- 本文：変更内容の概要と、動作確認した内容を簡単に

厳密なテンプレートは今のところ設けていません。まずはこの流れに慣れることを優先してください。
