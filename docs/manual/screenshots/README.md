## 記録事項

### クライアントの選び方（2-3-01・2-4-01 共通）

設定画面の「部署」「実施回」「管理者アカウント」タブは、`system_admin` でログインすると
ページ上部にクライアントセレクタが表示される。操作対象のクライアントをここで選ぶと、
そのクライアントに紐づく部署・実施回が表示される。  
撮影では「見本株式会社」（クライアントコード: `demo`）を選択した。

### 招待後の流れ（4-1 管理者アカウント）

1. `system_admin` が「管理者アカウント」タブで招待メールアドレス・ロールを入力し送信  
2. Supabase が招待メールを自動送信（`inviteUserByEmail` 経由）  
3. 招待された人がメール内のリンクをクリック  
4. アプリがリンクを受け取り `/change-password`（パスワード設定画面）へ転送  
5. 招待された人が新しいパスワードを設定  
6. 以降は通常のメール・パスワードでログイン可能  

なお `client_admin` は招待時に「所属クライアント」も選択する必要がある（4-1-02 参照）。

### 実施回削除の挙動（7-2）

**クライアント削除（7-2-01）**  
削除ボタンを押すと確認フォームが展開される。確認フォームにクライアントコードを入力するまで
「完全に削除する」ボタンは非活性（グレーアウト）のままで押せない。  
削除実行時は `delete_client_cascade` RPC を呼び出し、回答データ・部署・実施回・クライアントをこの順に手動削除する。  
（`qq_conditions` テーブルのレコードは対象外）

**実施回削除（7-2-02〜7-2-05）**  
回答がある実施回の削除を試みると、`survey_responses.survey_round_id` の FK 制約（NO ACTION）により
本番 DB ではエラーになり削除されない。  
ただしアプリはエラーを表示せずリストを再表示するため、UI 上は「削除ボタンを押しても何も起きない」
ように見える（7-2-03→7-2-04 参照）。  
回答が0件の実施回は FK 違反がないため正常に削除され、一覧から消える（7-2-05 参照）。
