## 1. ログインと画面の見方

### 1-1. ログイン方法

- 認証方式: **メールアドレス＋パスワード**（Supabase Auth の `signInWithPassword`）
- ログイン画面のフィールド:
  - メールアドレス（必須、type=email）
  - パスワード（必須、type=password）
  - ボタン: **「ログイン」**（処理中は「ログイン中...」と表示）
- ログイン成功後の遷移先:
  - `system_admin` → `/settings`
  - `client_admin` → `/results`
  - URL に `?next=〜` がある場合はそのパスへ遷移

根拠: `src/app/login/page.tsx` L25–41

### 1-2. パスワードを忘れた場合・変更する場合

**実装済み**。ログイン画面に「パスワードを変更する」リンクがあり `/change-password` に遷移する。

**フロー**:
1. `/change-password` でメールアドレスを入力し「**変更用リンクを送信**」ボタンを押す
2. メール（件名・本文は `supabase/templates/recovery.html`）が届く
3. メール内の「パスワードリセット」リンクをクリック
4. `/change-password` の「新しいパスワード」フォームが表示される
5. 新パスワード（8文字以上）を2回入力し「**パスワードを変更する**」ボタン
6. 「パスワードを変更しました」と表示され、「ログインページへ」リンクが出る

**パスワード要件**: 8文字以上（英数字の種別制限は不明・コード上は文字数のみチェック）

根拠: `src/app/change-password/page.tsx` L56–68、`supabase/templates/recovery.html`

### 1-3. 共通ナビゲーション（ヘッダー）

ログイン後のすべての画面（/settings・/results・/survey 系）に共通ヘッダーが表示される。

| 要素 | 表示内容 | 遷移先 |
|---|---|---|
| ロゴ（左） | 「健康管理システム」（ロゴアイコン＋テキスト） | `/`（→ `/login` にリダイレクト） |
| リンク（中央左） | `system_admin`: 「設定」、`client_admin`: 「部署・回答URL参照」 | `/settings` |
| ボタン（中央右） | 「分析結果」 | `/results` |
| テキスト（右） | ログイン中のメールアドレス（smサイズ以上で表示） | なし |
| ボタン（右端） | 「ログアウト」 | ログアウト後 `/login` へ |

根拠: `src/components/AppChrome.tsx` L36–77

### 2-3. 部署の設定

`system_admin` は追加・削除・並べ替えが可能。`client_admin` は閲覧のみ（「変更が必要な場合はシステム管理者にお問い合わせください。」と案内される）。

- テキスト入力（プレースホルダー「例：営業部」）→「追加」ボタン または Enterキーで追加
- ▲▼ボタンで並べ替え可能
- 「保存する」ボタンで確定（未保存の変更は失われる）
- 同じ名前は追加できない（重複チェックあり）

根拠: `src/app/settings/page.tsx` L539–590、`src/lib/storage.ts` L112–118

### 2-4. 実施回の作成

`system_admin` のみ作成・編集・削除可。`client_admin` は閲覧と URL コピーのみ。

**登録フィールド**:
| フィールド | 必須/任意 | 型 | 備考 |
|---|---|---|---|
| 実施回名 | 必須 | テキスト（プレースホルダー「例：第1回 2026年9月」） | |
| 開始日 | 任意 | 日付（type=date） | |
| 終了日 | 任意 | 日付（type=date） | 開始日より後の日付のみ指定可 |

**「追加する」ボタン。成功時「追加しました」と表示。**

**初回と再評価の関係**: 各実施回は独立したレコードとして `survey_rounds` テーブルに保存される。初回・再評価を区別するフラグはなく、**分析結果画面の「比較実施回（前回）」と「表示実施回（今回）」の2つのセレクトボックスで任意の2回を選んで比較する**仕組み。

根拠: `src/app/settings/page.tsx` L236–256、`src/lib/types.ts` L80–87、`src/app/results/ResultsDashboard.tsx` L309–339

## 3. 配布：回答URLの発行

### 3-1. 回答URLの生成ルール

**形式**: `{アプリのベースURL}/survey?client={クライアントコード}&round={実施回ID}`

- `{アプリのベースURL}`: 環境変数 `NEXT_PUBLIC_APP_URL`。未設定時は `window.location.origin`（ブラウザのURL）を使用
- `{クライアントコード}`: clients テーブルの `code` カラム値
- `{実施回ID}`: survey_rounds テーブルの数値 ID（自動採番）

例: `https://survey.so-tsuyama.co.jp/survey?client=soxx&round=3`

根拠: `src/app/settings/page.tsx` L287–290

**コピー方法**: 設定画面の「実施回」タブで各実施回の横に表示されるテキストボックスの「コピー」ボタン（`navigator.clipboard.writeText()`）。

根拠: `src/app/settings/page.tsx` L613–619

### 3-2. QRコード発行機能

**ソースコードにQRコード生成機能は見当たらない。不明欄参照。**

### 3-4. 回答の流れ

1. URL を開くと**プライバシーポリシー同意モーダル**が表示される
   - 本文: 「アンケートの結果は全体の集計結果として取りまとめ、個人の回答内容は会社に公開されることはありません。調査結果は学会、論文等で公表することがあります。」
   - ボタン: **「同意して進む」**
   - ✕ボタンまたは「同意して進む」以外で閉じると「個人情報の取り扱いへの同意が必要なため、アンケートを開始できません。」と表示されアンケートを進められない

2. 同意後、各設問画面を順に進む（画面上部にステップ番号と進捗バーを表示）
3. 各画面に「**戻る**」ボタン（最初の画面では無効化）と「**次へ**」ボタン
4. 最終画面では「次へ」の代わりに「**回答を送信**」ボタン
5. 送信完了後「回答ありがとうございました」画面に遷移

**ステップ数**: 最小5ステップ（問6で不調なし・モジュールなし）〜最大9ステップ（不調あり・全モジュールON）

**中断・再開**: ブラウザを閉じると入力内容は消える。フォームはブラウザのメモリ上にのみ保持される（サーバーへの途中保存なし）。

根拠: `src/app/survey/page.tsx` L225–321、`src/app/survey/_types.ts` L127–141

## 4. 回収：回答状況の確認と締め切り

### 4-1. 回答数・回答状況を確認できる画面

**管理者が回答件数を確認できる専用画面はない。** 分析結果画面（/results）のカード上部に「n人」と総回答者数が表示されるが、これは集計値であり個人の回答状況リストではない。

### 4-2. 回答期間の設定・締め切り操作

実施回の「開始日」「終了日」フィールドは設定できるが、**システムが自動的に受付を開始・終了する機能は実装されていない。** 日付はラベル目的のみで、URLは日付に関わらず常に有効である。

「受付終了」ボタンや「締め切り」操作もない。

終了後に回答URLを開いたときの表示: 特別な制御はなく、通常通りアンケートが表示される。

根拠: `src/app/survey/page.tsx` L61–78（clientExists チェックはするが日付チェックはなし）

### 4-3. 同じ人が二重に回答した場合

**重複チェック機能はソースコードに見当たらない。** 氏名＋生年月日の一意性チェックはなく、同じURLで何度でも回答を送信できる（各回答が独立したレコードとして保存される）。

根拠: `src/lib/storage.ts` L188–218（INSERT のみ、upsert・重複チェックなし）

### 5-5. 損失額の計算式

**プレゼンティーイズム年間損失（万円）**:
```
symptomDaysPast30 × 12 × (1 - workQuantity/10 × workQuality/10) × 1万円/日
```

**欠勤年間損失（万円）**:
```
absenteeDaysPastYear × 1万円/日
```

**各値の出所**:
| 変数 | 出所 | 設問 |
|---|---|---|
| `symptomDaysPast30` | 回答者の回答 | 問8: 直近30日間の有症状日数（0〜30） |
| `workQuantity` | 回答者の回答 | 問10: 症状があるときの仕事量（0〜10） |
| `workQuality` | 回答者の回答 | 問11: 症状があるときの仕事の質（0〜10） |
| `absenteeDaysPastYear` | 回答者の回答 | 問9: 直近1年間の欠勤日数（0〜365） |
| 1万円/日 | **コードに固定** | `DAILY_LABOR_COST_MAN_YEN = 1`（万円/日） |

「12か月換算」と「1万円/日の単価」はコードに固定されており、管理者が変更する手段はない。

根拠: `src/lib/qq-method.ts` L1–34、`src/lib/constants.ts` L4、`src/app/results/ResultsDashboard.tsx` L634–637

### 5-6. 痛みの部位（人体図）の集計方法

問6の症状選択IDを `CONDITION_TO_PAIN_DEFAULT`（`src/lib/constants.ts` L21–38）で痛み部位コードに変換し、部位別件数を集計。最大件数を1として正規化した「強度」で人体図の各部位の色の濃さを決定。

**部位コード → 表示部位のマッピング例**:
| 症状 | 痛み部位 |
|---|---|
| 腰痛 | 腰（lower_back） |
| 首の不調・肩こり | 首（neck）・肩（shoulder） |
| 頭痛 | 頭（head） |
| アレルギー疾患 | 頭（head） |

根拠: `src/lib/constants.ts` L21–38、`src/lib/analytics.ts` L125–136

### 5-7. 初回と再評価の比較表示

**操作**: 分析結果画面の「比較実施回（前回）」セレクトボックスで前回の実施回を選択すると比較モードになる。

**比較モードで変わる表示**:
- 各指標が「前回の値 → 今回の値」の形式で表示
- 増減バッジ（▲▼）が色付きで表示される
- 人体図は左右並列表示（左:前回・右:今回）
- 部署グラフも前回・今回を並べて表示
- CSVダウンロードボタンは比較モード中は非表示

**問7・問8の母数に関する注意点**:
- 問7（主な不調）・問8〜11（QQメソッド）は「問6で不調ありと回答した人のみ」が回答する設問。
- したがって前回と今回で「不調ありの人の比率」が異なれば、QQメソッド集計の母数（回答者数）が異なる。
- 問9の欠勤率の分母も「業務に支障がある人数」であり、全回答者数ではない。

根拠: `src/app/results/ResultsDashboard.tsx` L400–455、`src/lib/analytics.ts` L113–156

## 不明点・仕様との食い違いの可能性

### ソースから判断できなかったこと

1. **QRコード発行機能**: ソースに実装が見当たらない。管理画面に「QRコード」に関するコードなし。
2. **回答期間の自動開始・終了**: 実施回の開始日・終了日は入力できるが、URLのアクセスを日付で制限する処理はない。締め切り後も回答できる状態が続く。
3. **実施回削除時の回答データへの影響**: `deleteSurveyRound` は `survey_rounds` テーブルのレコードを削除するのみ。`survey_responses` の `survey_round_id` はNULL許容のため、DBのカスケード設定次第（マイグレーションファイルでの `ON DELETE` 設定を要確認）。
4. **重複回答の扱い**: 同じ人が何度でも回答できる状態。意図的かどうか不明。
5. **SPOS-J（問18）の本番リリース状況**: コードコメント（`src/app/survey/_steps/StepCompanySupport.tsx` L11–15）に「産業医科大学へのSPOS-J商用利用許可はまだ申請中・未回答。許可が下りるまでは本番（main）へのリリース不可」と記載。現時点での本番適用可否は要確認（メモリ記録 `project_issue20_pending_license.md`）。
6. **招待メールの本文**: Supabase のデフォルト招待メールが送信される。`supabase/templates/` に `recovery.html`（パスワードリセット用）はあるが、招待メール用テンプレートのカスタマイズは確認できない。

### 実装が要件・仕様書と食い違っていそうな点

1. **雇用形態の選択肢名**: コード上は「派遣・契約・委託」（`contract` のラベルとして）だが、設問設計書上での表記との一致は未確認。CSV出力では「契約社員」と表示される（`src/lib/csv-export.ts` L15 `contract: "契約社員"`）。アンケート画面表示（「派遣・契約・委託」）とCSV出力（「契約社員」）で**表記が異なる**。
2. **問7の非表示条件**: 問6で1つだけ選択した場合は問7が自動選択・非表示になる。この仕様はコメントに「藤田さん確認済み仕様、2026-08-19」とあるが、マニュアルでの説明要否は確認が必要。
